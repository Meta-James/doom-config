* Leader: =SPC a= (AI) — implemented

| Key       | Command                     | Evil state | Modes  | Rationale |
|-----------+------------------------------+------------+--------+--------------------------------------------|
| =SPC a i= | =gptel= (toggle chat popup) | normal     | global | Primary entry point |
| =SPC a s= | =gptel-send= (send region, get immediate response) | visual/normal | global | Distinct from "add as context" — this gets an answer now |
| =SPC a a= | =gptel-add= (built-in DWIM: add region/buffer/dired-marked-files/ibuffer-marked as context) | normal | global, Dired, IBuffer | One command, not three — its behavior is already context-sensitive; separate keys for "region"/"buffer"/"project" would have been artificial |
| =SPC a d= | =my/gptel-add-diagnostics= (new, Flycheck has no gptel integration) | normal | global | Explicit diagnostic context, genuinely not covered by any built-in |
| =SPC a r= | =gptel-rewrite= (built-in, ediff-based) | visual | global | Replaces the old scratch-buffer copy-paste rewrite flow entirely |
| =SPC a m= | =gptel-menu= (transient: backend/model/directive/tools) | normal | global | Provider switching frequent enough to deserve a direct key |
| =SPC a t= | =my/project-ghostel= (=config.el:216-226=; renamed from =my/project-vterm= 2026-08-17, [[id:adr-terminal-backend-ghostel][ADR-014]]) | normal | global | Also still bound at =SPC p t=; two legitimate entry points to the same command, not duplication of logic |
| =SPC a g= | =claude-code-ide-menu= (transient: session mgmt, navigation, interaction, config, debug) | normal | global | One binding, not two — the transient's own submenus cover launch/stop/status/list-sessions/diff-toggle; no separate "review" key needed since Ediff opens automatically on file changes (=claude-code-ide-use-ide-diff= =t=) |

No separate =SPC a R= was added — the original sketch assumed a distinct
review-trigger command would be needed; source inspection during Phase 6
([[id:adr-claude-code-ide-install][ADR-008]]) found Ediff review is automatic, and the transient menu already
exposes everything else (stop, list sessions, switch buffer, toggle window)
under =SPC a g='s own submenus rather than needing top-level leader keys.

* What changed from the original sketch

The Phase 1 proposal assumed three separate thin wrapper commands would be
needed for region/buffer/project context (=SPC a s=/=b=/=p=). Source inspection
during Phase 4 ([[id:adr-gptel-rework][ADR-006]]) found gptel already ships =gptel-add= — a single
DWIM command whose behavior depends on where it's invoked from (region active →
add region; in Dired with marks → add those files/directories recursively; in
IBuffer → add marked buffers; otherwise → add current buffer). Three keys
mapped to context-sensitive behavior that doesn't vary by which key was pressed
would have been artificial, so this collapsed to one binding (=SPC a a=) plus
the still-distinct =SPC a s= (immediate send, not context-add).

* Completion — verified (Phase 5, re-verified for Corfu in [[id:adr-corfu-migration][ADR-021]])

Non-AI in-buffer completion migrated Company → Corfu 2026-08-18 ([[id:adr-corfu-migration][ADR-021]]);
Doom's own README marked Company deprecated/maintenance-mode in favor of
Corfu. Vertico (minibuffer/=completing-read= axis) is unchanged.

| Key      | Behavior                                                        |
|----------+--------------------------------------------------------------------|
| =TAB=    | Copilot accept if a suggestion overlay is visible → else yasnippet field-navigate if a field is active → else Corfu cycle (=corfu-next=) if a popup is showing → else NES accept if an edit is pending → else indent/yasnippet |
| =RET=    | (Corfu popup showing) insert/accept the selected candidate (=corfu-insert=) — Corfu routes acceptance through =RET=, not =TAB=, unlike Company |
| =C-TAB=  | Copilot accept-by-word                                          |
| =M-n=/=M-p= | Cycle between multiple Copilot completion candidates (discovered in source, not previously documented) |
| =C-g=     | Dismiss a pending NES suggestion (=copilot-nes-mode-map=); regular Copilot overlays dismiss automatically on the next non-whitelisted command via =post-command-hook=, no dedicated key needed |

Live-verified in an isolated headless daemon (not the user's session;
disposable test daemons killed after use) via simulated overlays/keymap
state built from the real primitives (=copilot--get-overlay=,
=copilot-completion-map=, =yas-keymap=, =corfu-map= installed the same way
=corfu--setup= installs it), in both =evil-normal-state= and
=evil-insert-state= (identical results in both):
- Nothing active → =TAB= → =indent-for-tab-command=
- Corfu popup only → =TAB= → =corfu-next= (cycles; does *not* accept — accept
  is =RET=, a genuine behavior change from Company's TAB-accepts flow)
- Corfu popup + Copilot suggestion overlay → =TAB= → =copilot-accept-completion=
  (Copilot still wins outright, unchanged from the Company era)
- Corfu popup + real yasnippet field overlay (no Copilot) → =TAB= →
  =yas-next-field-or-maybe-expand= (yasnippet's overlay-keymap property still
  beats Corfu's =minor-mode-overriding-map-alist= entry — same relative
  ordering as Copilot-vs-yasnippet, since both are keymap-at-point checks
  ranked above Corfu's alist tier)
- Copilot overlay + yasnippet field, no Corfu popup → =TAB= →
  =copilot-accept-completion= (ADR-007's original finding, re-confirmed
  unchanged: Copilot's overlay priority 101 beats yasnippet's default 100)
- NES pending only → =TAB= → =copilot-nes-accept=
- Corfu popup + NES pending simultaneously (no regular Copilot overlay) →
  =TAB= → =corfu-next=, i.e. *Corfu wins*, not NES — a case ADR-007 never had
  to consider (no third overriding-map-alist layer existed yet). Low
  real-world likelihood since the two rarely trigger at once, but now
  documented rather than unknown.

One simulation mistake was caught mid-verification and is worth recording:
a first pass simulated the yasnippet field with a zero-width overlay, which
Emacs's keymap search does not reliably pick up at point at all (Corfu won
that malformed case by default) — real yasnippet fields always span their
placeholder text, so the overlay was corrected to real width before trusting
any result built on it.

Evil doesn't bind =TAB= in normal/insert/visual state (only in
=evil-command-line-map=, the Ex minibuffer) in this config — Doom's own
=[C-i]= rebind of =evil-jump-forward= (=editor/evil/config.el=) keeps plain
=TAB=/=C-i= free — so there's no Evil-vs-Copilot, Evil-vs-Corfu, or
Evil-vs-NES conflict in the states that matter. The GUI-only half of Doom's
=[C-i]=/=TAB= disambiguation hack (=doom-emacs.el= "HACK: Emacs can't
distinguish C-i from TAB") was not exercised by this verification — it needs
a real hardware keypress in a graphical frame to trigger at all, and it only
matters for =evil-jump-forward= reachability when no completion UI is active
in the first place, so it's orthogonal to the precedence chain above.

Not yet verified (needs the user's own authenticated session, not a headless
daemon): an actual live Copilot suggestion/NES-edit, and a real Corfu popup
built from genuine LSP/dabbrev candidates (not simulated keymap state),
appearing and being accepted/dismissed/cycled as expected.

* Conflicts resolved by ADR-003

- =SPC a= previously unbound Doom's default =embark-act= binding. Confirmed via
  the original code being dead ([[id:tshoot-dead-keybind-code][troubleshooting.org]]) — Embark-act was, in
  practice, still live at =SPC a= right up until this phase actually flattened
  the namespace. Now genuinely gone, live-verified.
- The intermediate "apps" prefix layer is removed; AI commands sit directly
  under =SPC a=.

* Alternatives considered and rejected

- =SPC A= (shifted, avoids touching Embark entirely) — rejected, unnecessary
  given the user doesn't need Embark on the leader at all.
- =C-c a= non-leader prefix — rejected, inconsistent with Doom's leader-first
  convention ([[id:std-doom-first][standards.org]]).
- Three separate context-add wrapper commands — rejected once =gptel-add='s DWIM
  behavior was found; see "What changed" above.
