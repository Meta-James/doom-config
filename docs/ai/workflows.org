One default, documented workflow per responsibility. Not implemented yet where
marked TODO — this is the target, cross-referenced from [[id:docs-roadmap][roadmap.org]] as each
phase lands.

* Chat (implemented — Phase 4)
:PROPERTIES:
:ID:       wf-chat
:END:

=SPC o l l= opens/toggles a gptel popup (=SPC o l L= for the same-window
variant). Since [[id:adr-llm-module-owns-ai-keys][ADR-028]] the whole chat surface is =:tools llm='s: it owns the
keymap, =gptel-default-mode=, and the popup rule — bottom, 0.3 height,
=:select t=, =:quit nil=, no TTL. That replaces [[id:adr-gptel-rework][ADR-006]]'s documented
right/0.42/=:quit t= rule, which had in fact never fired (it matched
=^\*gptel\*=, but gptel names the buffer =*Claude*= after the backend).

Default backend is Anthropic (=claude-sonnet-5=); switch provider/model/directive via
=gptel-menu= (=SPC o l m=). Send region for an immediate response with
=SPC o l s=; explain the thing at point in one shot with =SPC o l e=
(=gptel-quick=); add region/buffer/marked-files/a named file/diagnostics as
background context (no response triggered) with =SPC o l a=/=SPC o l f=/=SPC o
l d=. Org-mode is the default gptel buffer mode,
so chat transcripts are themselves Org and can be saved/linked like any other
document. Live-verified, both structurally (headless daemon: backend/model/
credentials wire up correctly) and interactively (user-confirmed: streaming,
cancellation, popup behavior, Org-buffer UX, and network-down behavior all
work) — see [[id:ai-evaluation][evaluation.org]].

*Chat history/privacy*: gptel doesn't maintain its own persistent chat log —
a chat buffer is an ordinary Org buffer that exists only in Emacs' memory
until the user explicitly saves it (=C-x C-s= to some file), exactly like any
other unsaved Org buffer. Nothing is written to disk automatically, and
nothing syncs anywhere beyond the configured provider (Anthropic/OpenAI) the
message content is sent to for a response — no separate logging layer this
project added. If the user wants a durable, searchable chat history, that's a
deliberate choice (save transcripts under some directory) rather than
something this config does implicitly.

* Focused transform (implemented — Phase 4)
:PROPERTIES:
:ID:       wf-transform
:END:

=SPC o l r= invokes the built-in =gptel-rewrite= on the active region — ediff/diff
-based in-place review, not the old copy-paste-from-scratch-buffer flow. Three
reusable instructions (=clearer=, =formal=, =summarize=) are registered in
=gptel-directives= and selectable from =gptel-rewrite='s own transient (its
directive-edit suffix). This replaced =my/gptel-rewrite-clearer/-formal=,
=my/gptel-summarize=, and =my/gptel--prompt-rewrite= entirely — see [[id:adr-gptel-rework][ADR-006]].

* Inline completion (implemented — Phase 5)
:PROPERTIES:
:ID:       wf-completion
:END:

Passive: copilot.el overlays a suggestion in supported =prog-mode= buffers.
=copilot-nes-mode= is also enabled on =prog-mode=, giving genuine
multi-location Next Edit Suggestions (=textDocument/copilotInlineEdit=)
alongside regular cursor-position completions. Non-AI in-buffer completion is
Corfu (Company → Corfu, [[id:adr-corfu-migration][ADR-021]]).

=TAB= precedence, live-verified (simulated overlays in an isolated daemon, not
assumed) in both Evil states: a pending Copilot suggestion overlay wins
outright (=copilot-accept-completion=) over everything else, including an
active Corfu popup; absent that, an active yasnippet field overlay wins over
a Corfu popup (=yas-next-field-or-maybe-expand=); absent that, a Corfu popup
cycles candidates (=corfu-next= — Corfu's own default, unlike Company, routes
*acceptance* through =RET= [=corfu-insert=], not =TAB=); absent that, a
pending NES edit is accepted (=copilot-nes-accept=); otherwise =TAB= falls
through to ordinary indent/yasnippet-expand behavior. The one case ADR-007's
Company-era chain never had to cover — a Corfu popup and a pending NES edit
coinciding with no regular Copilot overlay — resolves to the Corfu popup
(=corfu-next=), since Corfu's =minor-mode-overriding-map-alist= entry outranks
NES's plain =minor-mode-map-alist= entry. See [[id:adr-copilot-nes][ADR-007]] (original Company-era
verification) and [[id:adr-corfu-migration][ADR-021]] (Corfu re-verification) and [[id:ai-keybindings][keybindings.org]] for the full
chain, including the yasnippet-overlap edge case.

*Network/offline behavior*: suggestion and NES requests
(=textDocument/inlineCompletion=, =getPanelCompletions=, etc.) go through
=copilot--async-request= → =jsonrpc-async-request= — genuinely asynchronous,
not a blocking call on the main thread. Read directly from source
(=copilot.el=): a network failure fails that one async callback, it doesn't
block typing or freeze Emacs. Not separately live-tested against an actual
severed connection.

*Remote (TRAMP) buffers*: copilot.el's source has no TRAMP-specific handling
at all (checked — no =tramp=/=remote= references outside an unrelated MCP
config example). Behavior on a remote-visited buffer is genuinely unverified
here, not just untested-but-presumed-fine; upstream doesn't appear to have
designed for it. Treat as unsupported until someone actually tries it.

* Full agentic coding (installed, wired, and live-verified — Phase 6)
:PROPERTIES:
:ID:       wf-agent
:END:

=SPC o l g= opens =claude-code-ide-menu=, the single entry point (session
management, navigation, interaction, config, and debug submenus). One Claude
instance per project (via =project.el= auto-detection). Plan → multi-file edit
→ run formatters/tests → present diff via Ediff (opens automatically,
=claude-code-ide-use-ide-diff= =t=) → user accepts/rejects per hunk. Agent may
commit/push, but only with explicit, in-the-moment approval each time (see
[[id:std-no-commit][standards.org]]). Terminal backend: ghostel
(switched from vterm 2026-08-17, see [[id:adr-terminal-backend-ghostel][ADR-014]]). Diagnostics backend: Flycheck,
matching the existing Python stack.

Verified structurally (headless daemon): package loads, settings applied,
keybinding resolves, CLI correctly detected via a local, network-free check.

Verified live (user-approved real smoke test, [[id:adr-claude-code-ide-install][ADR-008]]): launched a real
session against a disposable scratch project, gave it a task with a
deliberately seeded bug, and watched it inspect, plan, edit, run pytest, hit
the failure, fix it, re-run to confirm, and stop cleanly — without touching
git. Along the way this also surfaced and fixed a real prerequisite gap:
vterm's native module had never been compiled on this machine (see
[[id:tshoot-vterm-module][troubleshooting.org]]), which would otherwise have silently blocked this
workflow (and =my/project-vterm=) the first time either was used for real.

*Not yet exercised*: interactive interruption/partial-rejection mid-session
(needs a human actually present, not a scripted test) and anything requiring
a remote/TRAMP target (needs hardware this agent doesn't have).

Re-verified live under the =ghostel= backend (2026-08-17, [[id:adr-terminal-backend-ghostel][ADR-014]]): same
seeded-bug task, fresh disposable scratch project, isolated headless
daemon — found the bug, fixed it, tests passed, marker file written, no git
commands run, independently confirmed on disk afterward. Along the way
surfaced a new backend-specific gotcha: ghostel needs a real graphical (X11)
frame to function, unlike vterm's plain-PTY approach (see
[[id:tshoot-ghostel-needs-x-frame][troubleshooting.org]]).

*=tdd= skill (recommended, not default, per [[id:adr-mattpocock-skills-adoption][ADR-016]])*: for well-specified
feature work with a clear, testable behavior, prefer writing the test first
via the =tdd= mattpocock-skill. This does not replace the plan → edit → test →
Ediff-review default above — exploratory/UI work (most edits in this repo)
keeps the existing workflow.

* Review (existing tools, no new package)
:PROPERTIES:
:ID:       wf-review
:END:

Magit for the git-level view, Ediff for the agent's proposed diff specifically,
Flycheck/LSP diagnostics re-run after any agent edit. No replacement of Magit as
the git authority.

* Terminal-hosted agent sessions (existing)
:PROPERTIES:
:ID:       wf-terminal
:END:

Doom's =ghostel= module is the terminal host, replacing vterm on 2026-08-17
([[id:adr-terminal-backend-ghostel][ADR-014]]) — both =my/project-ghostel= (renamed from
=my/project-vterm=) and claude-code-ide.el share it. This section previously said
vterm was the host and that no =eat=/=ghostel= adoption was planned; that was
already contradicted by [[id:wf-agent][the agent workflow section]] below and is
corrected here.
